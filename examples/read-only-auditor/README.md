This agent inspects systems and produces audit reports, and it should never change anything it looks at. Without policy, a read-only agent can drift: an injected instruction could turn a scan into a write, push a request at an internal metadata endpoint, or quietly carry a secret out in a fetch. This is the most locked-down example. It is read-only at the transport layer: only typed HTTP GET and HEAD requests are authorized, and the method check fails closed, with no shell, file writes, email, or wallet access. It pins requests to the listed audited hostnames (shipped as placeholders to replace with your audited surfaces), denies listed private-network and metadata hostnames, denies plain-http URLs, denies listed credential strings as defense in depth, requires a declared read-only job type, and sets very low execution limits. A GET endpoint that performs a server-side write remains the operator's residual risk.
