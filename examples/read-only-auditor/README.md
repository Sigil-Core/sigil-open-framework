This agent inspects systems and produces audit reports, and it should never change anything it looks at. Without policy, a read-only agent can drift: an injected instruction could turn a scan into a DROP or DELETE, push a request at an internal metadata endpoint, or quietly carry a secret out in a fetch. This is the most locked-down example. It permits web_fetch only, with no shell, file writes, email, or wallet access; it denies any write or mutate intent (DROP, INSERT, UPDATE, DELETE, TRUNCATE, rm), blocks SSRF and metadata endpoints, denies secret exfiltration, requires an allowlisted read-only job type, and sets very low execution limits.
